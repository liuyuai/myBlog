# 多轮记忆压缩：给上下文"瘦身"

> 「AI Agent 工程实践」系列 · 进阶篇第 3 篇。
> 解决多轮对话的窗口与成本问题。
> 相关：[记忆系统](./memory.md) / [大模型基础](./llm-basics.md)

## 为什么要压缩

多轮对话 → messages 无限增长 → 两个问题：

1. **撑爆上下文窗口**：超窗直接报错或截断输入；
2. **成本滚雪球**：每轮都要重发全部历史，token 按调用次数累加。

算一笔账：每轮平均 500 token，50 轮就是 25K token 的历史，还没算输出。

## 方案演进

| 版本 | 方案 | 优点 | 缺点 |
| --- | --- | --- | --- |
| v1 | **截断（滑动窗口）**：只留最近 N 轮 | 零成本 | 丢关键信息（开头说的需求） |
| v2 | **摘要压缩**：旧对话压成摘要 + 保留最近 N 轮 | 信息保留好 | 花一次模型调用，摘要可能失真 |
| v3 | **关键信息抽取**：只抽事实/决定/待办，结构化存储 | 精确、省 | 要设计抽取 schema |
| v4 | **分层摘要 + 向量**：对话→天→周多级摘要，按需检索 | 可扩展 | 最复杂 |

## 压缩时机

| 触发 | 说明 |
| --- | --- |
| 长度阈值 | 历史超过窗口 50% 时触发 |
| 轮数阈值 | 超过 N 轮触发 |
| 任务边界 | 每完成一个子任务压一次 |
| 空闲时 | 后台异步压缩，不阻塞对话 |

## v2 摘要压缩的实现（JS 示意）

```js
async function compressHistory(messages, keepRecent = 6) {
  const system = messages.filter(m => m.role === 'system');
  const history = messages.filter(m => m.role !== 'system');
  const recent = history.slice(-keepRecent);              // 保留最近 N 轮
  const old = history.slice(0, -keepRecent);              // 旧对话去压缩

  const summary = await callLLM({
    messages: [{
      role: 'user',
      content: `把以下对话压缩成要点，必须保留：用户需求、关键事实（数字/专有名词原样保留）、未完成事项、用户偏好。只输出摘要：
对话：${JSON.stringify(old)}`
    }]
  });

  return [
    ...system,
    { role: 'user', content: `【历史摘要】${summary}` },  // 摘要顶替旧对话
    ...recent
  ];
}
```

关键点：**摘要要"保留可核实的原话"**（数字、专有名词原样保留），而不是让模型自由改写——否则摘要失真会被后续对话继承放大。

## 注意（坑）

1. **摘要会丢细节**：数字、专有名词、用户原话——关键信息用**抽取**而不是摘要；
2. **压缩本身花 token**：一次压缩 ≈ 一次短调用，别压太频繁；
3. **压缩后模型会"忘"**：之前承诺过的事，摘要没记就没了——关键承诺进结构化记忆（见[记忆系统](./memory.md)）；
4. **用户说"我刚才说过"**：摘要可能答不上来——配合向量记忆做全文检索兜底；
5. **生产组合**：滑动窗口 + 滚动摘要 + 关键信息结构化，三者配合，别只用一种。

## 总结

压缩的本质是"用摘要换窗口"。单轮对话无所谓，多轮 Agent 不做压缩，成本和窗口迟早爆炸。下一篇讲 Agent 接工具的行业标准——[MCP 协议](./mcp.md)。
