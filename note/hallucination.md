# 幻觉：成因与缓解

> 「AI Agent 工程实践」系列 · 基础篇第 5 篇。
> 幻觉是 Agent 的头号风险，贯穿所有场景，单独成篇讲透。
> 相关：[RAG](./rag.md) / [HITL](./hitl.md) / [提示词工程](./prompt-engineering.md)

## 什么是幻觉

幻觉（Hallucination）指模型生成**看似合理但错误**的内容：编造事实、张冠李戴、自信地胡说。

分两类：

| 类型 | 含义 | 例子 |
| --- | --- | --- |
| 事实幻觉 | 与外部事实不符 | 编造一个不存在的 API |
| 忠实性幻觉 | 与给定上下文不符 | 资料里没写的，它"脑补"出来 |

## 为什么会发生

1. **训练目标是"预测下一个 token"**，不是"保证正确"——模型学的是统计规律；
2. **知识压缩损失**：模型记住的是"规律"不是"数据库"，细节天然丢失；
3. **解码采样引入随机性**：temperature 越高越容易发散；
4. **上下文诱导**：问题本身带错误前提，模型容易顺着说。

## 怎么检测

| 手段 | 原理 | 局限 |
| --- | --- | --- |
| 要求引用来源 | 让模型给出处 | 引用也可能编造，需要二次校验 |
| 置信度自评 | 让模型标 confidence | 模型普遍过度自信，只能参考 |
| 交叉验证 | 多个独立调用对比 | 贵、慢 |
| 检索核对 | 用 RAG 结果比对回答 | 依赖检索质量 |
| LLM-as-judge | 另一个模型判分 | judge 自己也会幻觉 |

检测手段都有盲区，**高风险场景必须人来兜底**。

## 怎么缓解（按性价比）

1. **给依据（最有效）**：RAG 注入资料 + 要求"只基于资料回答，资料没有就说没有"——把"猜"变成"查"；
2. **给工具**：能算的别猜、能查的别编——计算、查库、调 API；
3. **约束提示**：负面清单"不要编造""不确定说不知道"；
4. **降低随机性**：结构化任务 temperature 调低（0~0.3）；
5. **过程可见**：暴露思考与依据，让人可复核；
6. **高风险兜底**：不可逆动作走[HITL](./hitl.md)确认闸门。

## 一个对比示例

```text
❌ 无约束：模型编造 "退款 3 个工作日到账"
✅ 有约束 + RAG：模型回答 "根据客服文档，退款 1-2 个工作日到账"，并附来源片段
```

同样是"回答"，一个在猜，一个在查。

## 注意（坑）

1. **幻觉无法消除，只能降低 + 兜底**——宣称"零幻觉"的都是营销话术；
2. **链式放大**：Agent 第一步的小幻觉会被后续步骤不断引用放大，检查点越早越好；
3. **提示词里写"不要幻觉"作用有限**：给依据比喊口号有用得多；
4. **幻觉与场景强相关**：开放式闲聊无所谓，金融/医疗/合同场景必须严控。

## 总结

幻觉是模型的"出厂设置"：成因在训练目标，缓解靠"**给依据 + 给工具 + 过程可见 + 人兜底**"。记住一句话：不可逆、高风险的操作，幻觉必须由 HITL 闸门兜住。
