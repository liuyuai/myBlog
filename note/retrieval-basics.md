# 检索基础：BM25 与关键词检索

> 「AI Agent 工程实践」系列 · 基础篇第 3 篇。
> [RAG](./rag.md) 篇的"混合检索"直接用了 BM25，这篇补原理。
> 相关：Embedding 与向量检索 / 意图路由

## 倒排索引

关键词检索的底层结构是**倒排索引**（inverted index）：

- 正排：文档 → 词（想找词得遍历所有文档，慢）；
- 倒排：词 → 文档列表（词典 + 每个词对应的文档 id 列表）。

检索时：把 query 分词 → 查词典 → 合并文档列表 → 打分排序。

## TF-IDF 的直觉

- **TF**（词频）：一个词在文档里出现越多越重要。但"的""了"这种词出现最多，却没意义；
- **IDF**（逆文档频率）：一个词在越少文档里出现越稀有、越有区分度。"量子计算"很稀有 → IDF 大；"的"到处都是 → IDF 趋近 0。

得分直觉 = TF × IDF。这是 BM25 的前身。

## BM25：加了两处修正

BM25 在 TF-IDF 基础上主要修了两点：

1. **词频饱和**：词频到一定程度后，继续增加不再线性加分（参数 `k1`，通常取 1.2~2.0）；
2. **长度归一化**：文档越长，词频越要打折——短文档里出现 3 次，比长文档里出现 3 次更能代表该文档（参数 `b`，通常取 0.75）。

一句话直觉：**BM25 看的是"这个词在相对短的文档里多次出现"，而不是"出现次数多"**。

## 为什么关键词检索仍不可替代

| 场景 | 例子 | 向量检索 | BM25 |
| --- | --- | --- | --- |
| 专有名词 | iPhone 15 Pro Max 256G | 差（语义漂移） | 好（精确命中） |
| 代码 / 变量名 | getUserById | 差 | 好 |
| 精确数字 / ID | 订单号 20260920 | 差 | 好 |
| 口语化表达 | "帮我看看快递到哪了" | 好 | 差（缺同义词扩展） |

结论：**语义检索懂"意思"，关键词检索懂"字面"**。生产 RAG 通常两者都要——向量捞语义、BM25 捞关键词，再用 RRF 融合排序（实现见 [RAG](./rag.md) 篇的进阶二）。

## 一个玩具实现（JS）

```js
// 简化版 BM25 打分示意（生产请用成熟库，如 Lucene / ES / Meilisearch）
function scoreBM25(queryTokens, doc, idf, avgDocLen, { k1 = 1.5, b = 0.75 } = {}) {
  let score = 0;
  const tf = {};                                   // 词频统计
  for (const t of doc.tokens) tf[t] = (tf[t] || 0) + 1;
  for (const t of queryTokens) {
    if (!(t in tf) || !(t in idf)) continue;
    const len = doc.tokens.length;
    const denom = tf[t] + k1 * (1 - b + b * len / avgDocLen);
    score += idf[t] * (tf[t] * (k1 + 1)) / denom;
  }
  return score;
}
```

中文要先分词（jieba 等），不做分词的"按字切"会让匹配质量烂到没法用。

## 注意（坑）

1. **中文必须分词**，直接按字匹配基本不可用；
2. **停用词要过滤**：的 / 了 / 是 这类词只会污染打分；
3. **同义词无能为力**："退款"和"退钱"在 BM25 里是两个字面不同的词——这类变体交给[意图路由](./intent-routing.md)或向量检索；
4. **索引要随文档更新**：删改文档后索引不重建，会搜到旧内容。

## 总结

BM25 是"字面匹配"的黄金标准，擅长专有名词、代码、ID；向量检索擅长语义。两者互补，生产 RAG 用混合检索。下一篇讲模型的"思考方式"——[推理范式：CoT / ReAct / Plan-and-Execute](./reasoning-paradigms.md)。
